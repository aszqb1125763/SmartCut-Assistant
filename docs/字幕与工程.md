# 字幕与工程

## 字幕产物

SmartCut 可以生成与剪辑后时间轴对应的 `.srt` 和 `.ass` 文件，也可以在普通视频输出时选择烧录字幕。

- 关闭烧录：保留独立字幕文件，便于平台上传或后期修改。
- 开启烧录：字幕成为视频画面的一部分，后续无法单独关闭。

字幕时间会随删除片段重新映射。交付前仍建议检查专有名词、同音字和句尾时间。

从 1.1.4 起，默认字幕为单行，按“一句一个意思”分段，目标和上限约 15 个汉字。分段优先使用完整句标点、真实语音停顿和“但是、然后、所以、我们、这个”等语义边界，长度只作为最后兜底。有词级时间证据时，分段起止点取自对应词，而不是按字符数平均猜测。程序不会为了适应版式裁字或自行添加省略号；极少数无法与词级证据对应的旧索引，才会使用保守的比例时间回退。

交付字幕采用四层流水线：

1. **识别与时间证据**：在用户选中的实际音轨上运行 `faster-whisper`，准确档默认为 `large-v3 + beam 5`，保存句级和词级时间；Silero ONNX VAD 只用于核对人声覆盖，不把音乐、游戏音效或普通高能量噪声误当成口播。
2. **局部复听与时间修复**：检测低置信词、孤立单字、疑似断词、单字超长、词间巨大空洞、父段覆盖异常和连续人声漏识。只截取异常前后的短窗口，用当前选中的同一 ASR 档位重新听写；新结果必须通过时间、锚点和覆盖复检，失败时保留较可靠的旧结果并记录疑点，不重跑整部素材。
3. **术语与上下文校对**：先从原始 ASR 证据恢复旧校对误删的字，再用用户词表和本片唯一长别名执行确定性纠正；全部非空台词按批次交给当前所选本地模型或已配置的 API，并提供前后文只读上下文。模型建议不得概括、扩写、删除口播字或新增省略号，数字、人称、说话人和专业词的变化都会经过保真检查；接受项、拒绝项与回退项写入 `字幕校对报告.json`。
4. **语义断句与双语交付**：按语义边界和词级时间生成约 15 字的单行字幕，再映射到剪辑后的紧凑时间轴。简体和繁体共用完全相同的条数与时间点，只转换文字，不分别重切时间。

字幕是交付增强项，不是视频和工程的硬前置条件。局部复听、模型校对、Silero 检查或个别字幕行失败时，程序会降级到已验证的原始 ASR、跳过损坏行并写入警告；即使整个字幕模块异常，普通视频和可编辑 Premiere 工程仍应继续生成。遇到索引结构损坏时不会伪造字幕证据，但也不会因此丢掉已经完成的剪辑工程，用户可以重新分析后单独补字幕。

逐词时间校验完成后，程序会在实际识别所用的音轨上做一次保守的局部波形边缘微调。每个起点和终点最多移动 0.25 秒；首词、末词是硬边界，持续有声、没有清晰边缘或会造成相邻字幕重叠时保持原时间。该步骤不合并、不删除字幕，也不改变文字。精修结果会记录源素材身份、音轨、ASR 配置、字幕条数和 `segment_id` 顺序；其中任一项变化，或遇到旧版精修缓存，导出都会自动退回原始逐词时间，避免错误音轨和过期索引造成字幕错位。

语音识别默认使用软件保存的准确档；新安装默认 `large-v3 + beam 5`。索引会保存模型、解码、VAD、提示词和热词签名，旧索引或设置变化会自动重建，避免表面切到准确档却继续复用旧转写。快速档仍可由用户明确选择。

### 设计来源与边界

本流程借鉴了剪映专业版公开界面中“语言检测、自定义词汇、智能断句、去水词/翻译分层处理”的产品思路，并结合公开的 Whisper、Silero VAD 等方案重新实现。SmartCut 不反编译、不调用剪映内部私有接口，也不复制其专有代码。为避免漏字，SmartCut 默认不会自动删除“嗯、呃、啊”等口头语；它们会尽量并入相邻语义句，是否删除应交给内容剪辑或用户后期决定。

## Premiere 工程

Premiere 工作流输出 `.prproj` 工程，而不是只能观看的视频。它保留源媒体引用、片段时间轴和所选音轨，因此可以继续：

- 调整片段入点、出点和顺序。
- 恢复更多源素材时长。
- 继续混音、加效果、调色和替换字幕。

SmartCut 默认另存工程并保留剪辑前备份。不要在移动源素材后直接打开工程；若 Premiere 提示媒体脱机，请重新链接原素材。

### 简繁双字幕

生成 PR 工程时，SmartCut 会先在源时间顺序完成安全校对，再把台词按最终保留片段映射到剪辑后时间轴，在最终 `.prproj` 同目录写入 `_简体中文字幕.srt` 和 `_繁体中文字幕.srt`。两条字幕共用同一组分页时间点，简体输出会进行繁转简，繁体输出会进行简转繁；缺少完整转换字典而采用降级转换时，日志会提示，需抽查异体字和多音义字。

支持 `Sequence.createCaptionTrack` 的 PR 会在工程中自动创建简体、繁体两条原生可编辑字幕轨。可以在 PR 中修改字幕文字、时间、样式，并按交付需要切换语言轨。

PR 缺少该接口，或者其中一条字幕轨创建失败时，工作流会启用兼容模式：先确保两份 SRT 已导入项目面板，继续保存最终工程；日志会说明未自动建轨的原因。把所需 SRT 从项目面板拖入序列即可继续编辑，已经创建成功的轨道会保留。不要把“原生建轨失败”误认为整个 PR 工程生成失败。

请将工程和两份 SRT 保留在同一文件夹，备份或转移工程时一起复制；原始视频、音频素材也要保留，工程不包含这些媒体文件本身。安装方式、支持范围及旧版 PR 限制见[Premiere 插件](Premiere插件.md)。

## 交付检查

1. 抽查开头、结尾和高密度对白段。
2. 确认没有半个词、吞尾音或过长静音。
3. 检查字幕与最终时间轴同步。
4. 检查工程音轨数量和静音状态。
5. 在另一台机器打开工程时验证媒体链接。
