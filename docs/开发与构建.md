# 开发与构建

本文针对 SmartCut 智能剪辑助手 1.1.6，面向希望自行修改代码、替换模型或让 AI 协助二次开发的用户。先读 [README](../README.md)、[安装指南](安装指南.md)，再按改动范围选择模块和验证方法。

## 开发环境与启动

推荐 Windows 10/11 64 位和 Python 3.12。在项目根目录执行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe app_main.py
```

`requirements.txt` 是运行依赖；`requirements-dev.txt` 额外包含 PyInstaller。FFmpeg、llama.cpp 和模型权重不属于 pip 依赖，由安装器按需准备。源码测试优先使用 `.venv` 的解释器，避免系统 Python 与打包环境混用。

`app_main.py` 是正式启动入口，负责启动模式和打包兼容。`启动SmartCut.bat` 会优先打开目录中的打包版 EXE，再回退到源码环境。`install_exe.py` 是历史上改名 pythonw 的兼容工具；新发行包使用 `build_tools/build_app.py`，不要把两种方案混装。

## 模块架构与改动入口

- 产品元数据：[product_info.py](../product_info.py) 维护名称、产品 ID、版本和署名。`build_tools/version_info.txt` 是 Windows 文件属性模板，发布时应与其同步。
- 桌面界面：[ui_main_v2.py](../ui_main_v2.py) 是新版主窗口；[cards_ui.py](../cards_ui.py) 保留素材卡片、导出、字幕和训练对话框。设置在 `ui_settings.py`，队列在 `ui_queue.py` 与 `ui_queuepanel.py`，视觉样式在 `ui_theme.py` 与 `ui_widgets.py`。
- 分析层：[index.py](../index.py)、`asr.py`、`audiofeat.py`、`frames.py` 和 `brains/` 生成转写、音频、画面及中立标签。`brains/` 各插件应只观察本域证据，避免互相调用产生隐性依赖。
- 工作流：[workflow_engine.py](../workflow_engine.py) 定义岗位、依赖、任务合同和执行原语；[autopilot.py](../autopilot.py) 注入正式岗位处理器，`autoedit.py` 等入口复用同一流程。
- 内容决策：`script_writer.py` 编排故事结构，`model_editor.py` 生成事件级剪辑单，`autocut.py` 执行规则和保留区间整理，`genre.py` 与 `edit_modes.py` 提供内容专项策略。
- 边界与复审：`boundary_refiner.py`、`seam_picker.py`、`seam_continuity.py` 检查切点和接缝；`director_critic.py`、`director_multimodal.py`、`director_issue_ledger.py` 组织质量问题和返工；`rendered_output_qc.py` 检查实际输出。
- 渲染与字幕：`export.py`、`bgm.py`、`subtitles.py` 执行视频、混音、语义断句和字幕输出；`subtitle_quality.py` 负责词级质量门禁与局部复听，`proofread.py` 处理术语和上下文校对，`pr_subtitles.py` 映射并写入 Premiere 简繁字幕。识别证据、文字校对、语义分段、时间映射和画面样式属于不同职责，不应合并成一个不可测试的步骤。
- 共享缓存：`media_identity.py` 确认素材身份，`audio_evidence_cache.py` 与 `video_frame_cache.py` 复用音频和画面证据。缓存键必须区分源文件和所选音轨，修改证据算法时应审查失效策略。
- 任务恢复：`task_memory.py`、`memory_config.py` 管理任务状态、岗位日志、检查点和恢复。新增岗位状态时要同步查看恢复与取消测试。
- Premiere 集成：`sync_server.py` 提供本机服务，`pr_workflow.py` 对接正式剪辑链，`pr_engine.py` 支持面板的单步建议；`pr_bridge/` 包含 CEP 面板与 Premiere 内执行的 ExtendScript。
- 安装与发布：`setup_windows.ps1` 解决 Python 引导，`installer.py` 配置当前目录，`安装器.py` 复制到指定目录，`make_release.py` 生成干净发行包。

## 岗位工作流与合同

正式阶段顺序由 `workflow_engine.STAGE_ORDER` 定义：`analyze → writer → editor → boundary → director → transition → renderer → finalize`。分析型、普通成片和 Premiere 工程是不同工作流类型，不应为每个入口另写一套内容决策。

1. 分析员读取原片、选定音轨和画面，建立可回查的中立证据，不提前决定最终删留。
2. 编剧整理目标、过程、结果、章节和过渡，引用已有事件；不直接操作 PR 或渲染视频。
3. 剪辑师在事件合同范围内给出删留建议；代码校验事件 ID、范围和结构后转换成保留区间。
4. 边界岗位依据词句、音频包络和画面证据微调切点，保护起音与尾音。
5. 导演检查结构和视听问题，根据有证据的问题返工；问题、修改和残留限制应进入任务记录。
6. 转场与渲染岗位生成交付物；最终阶段记录质量状态、文件路径和必要的限制。

模型输出成功不等于交付通过。查看阶段结果、`director_passed`、问题记录和实际产物。若某条路径允许带问题交付可编辑工程，必须保留问题与降级状态；不要把可编辑中间结果标成无条件通过。

新增功能时优先添加可独立测试的处理器或证据函数，再从已有岗位接入。界面只收集参数与显示状态，不应直接复制编剧、剪辑和导演的实现。

## 时间坐标、音轨和切点

这里至少有三套坐标：源素材时间、PR 当前序列时间、剪辑后输出时间。字段名中明确写出坐标含义，不能因为数值都以秒表示就直接混用。

- [source_timeline.py](../source_timeline.py) 把有对白的区间转换为 `U` 事件，把无转写覆盖的区间转换为 `G` 事件，采用稳定 ID 和版本指纹。`G` 只表示没有转写证据，不能单凭此断言画面或声音没有意义。
- 一段素材在 PR 中的速度为 1 且未倒放时，若原片入点为 `source_in`、序列起点为 `sequence_start`，可按 `sequence_time = sequence_start + source_time - source_in` 映射。变速、嵌套、多源或不支持的布局必须经过已有校验，不套用这个简式。
- 普通拼接按保留区间累计输出时长。若原片 `[10, 15]` 秒映射到成片 `[0, 5]` 秒，则原片 12 秒对应成片 2 秒。字幕必须复用该映射，不能继续使用原片时间。
- Premiere API 中的 ticks、媒体采样率、视频帧率、UI 显示的秒数各有单位。只能在边界处转换；不要把小数秒直接写入要求 ticks 的字段。
- 用户看到 `A1/A2`，Python 内部音轨索引通常从 0 开始。所选轨用于 AI 分析；最终工程保留全部原轨还是仅选中轨，是另一个设置。

[coords.py](../coords.py) 是声音、画面和切点判据的统一来源；选择器、审计器与质量检查应引用同一阈值和量纲。[cut_strength.py](../cut_strength.py) 统一内容保留百分比，当前范围为 15%～100%；`cut_level` 是由百分比派生的旧链路兼容策略，用户设置以 `keep_ratio` 为准。不能只把 UI 改成百分比却在工作线程中丢掉精确比例，也不能用长时间无对白空段凑保留时长。

## API 与本地模型适配

设置字段和服务预设在 [ai_api_settings.py](../ai_api_settings.py)，网络适配在 [llm_gateway.py](../llm_gateway.py)，统一模型配置与客户入口在 [llm_config.py](../llm_config.py)。本地 llama-server 的启动桥位于 `ui/llm_bridge.py`。用户操作见 [API 模型配置](API模型.md)。

API 的独立角色输出合同、编号和字段验证在 [ai_api_contracts.py](../ai_api_contracts.py)。新增一种输出任务时，要同时扩展合同识别、远端角色提示、返回校验与模拟测试，不要将旧本地 system 提示直接透传给远端。`llm_gateway.backend_signature()` 区分提供方、地址、模型与合同版本，供剧本、索引语言标签和任务恢复判断缓存是否有效。底层媒体证据缓存可继续共享。

API 模式与本地模式应共用岗位输入输出合同，但远端请求、角色提示、鉴权和端点协议由适配层负责。不要把所有服务商都硬套同一种 URL 或认证格式；也不要在 UI、编剧和导演内部各自拼请求。新增服务商时，先明确：提供方 ID、默认地址、模型 ID、鉴权方式、超时、返回内容解析、JSON 输出合同和脱敏错误。

模型应引用已授权的事件 ID 或当前合同允许的区间。无效 JSON、未知事件、越界区间、超时和 HTTP 400/401 等都要显式记录，避免把失败当作空剪辑结果。回归测试应使用模拟响应，不消耗用户额度。

API Key 当前保存在本机 `conf/settings.json`，不进入公共仓库和干净发布包。日志只输出经脱敏的服务名、模型名和错误摘要。API 可能收到完成任务所需的文本或画面证据；涉及敏感内容时先使用本地或自建服务。

所有可写配置、模型路径和日志都应尊重 `SMARTCUT_HOME`，共用 `memory_config.app_home()`；打包后默认指向 EXE 所在目录。不要从 PyInstaller 的 `_internal` 读取用户设置。`test_installation_paths.py` 覆盖配置根路径与 API 模式免本地语言模型的检查。

## Premiere / CEP 通信

1. `pr_bridge/index.html` 和 `pr_bridge/js/main.js` 在 CEP 面板中运行，使用 `CSInterface` 调用 `pr_bridge/jsx/host.jsx`。
2. `host.jsx` 在 Premiere 内读取当前序列、轨道、片段入出点与素材路径；面板将序列快照发给本机服务。
3. `sync_server.py` 默认监听 `127.0.0.1:17890`。常用接口为 `GET /health`、`POST /sequence`、`GET/POST /audio-settings`、`POST /smart-edit/start`、`GET /smart-edit/status`、`GET /smart-edit/result`。单步功能另用 `/view` 与 `/step`。
4. `pr_workflow.run()` 调用 `autopilot.run_one(..., workflow=PREMIERE_EDIT)`，把源素材保留区间映射为当前 PR 序列可执行的操作，并携带序列指纹。
5. 面板获取结果后由 Premiere 侧执行，另存可编辑工程并保留原工程备份；字幕时间映射与原生轨处理属于专门模块，不应在面板里重新计算。

完整剪辑开始时应冻结当前时间轴和音轨设置；执行前再核对序列指纹。分析期间用户移动了片段、替换素材或改变音轨时，不应把旧计划套到新序列。阅读 `pr_workflow._validate_sequence()` 了解当前单素材等适用限制，扩展支持前要增加映射和事务测试。

本机桥不是公开远程服务。开发中不要把监听地址改为公网地址或暴露能执行时间轴操作的端点。面板、服务、ExtendScript 和原生命令辅助程序应成套更新；修改脚本后完全退出并重启 Premiere。

## 测试与复现

先运行与改动直接相关的测试，再按风险扩展。Qt 可采用离屏模式，避免测试窗口干扰当前剪辑：

```powershell
$env:QT_QPA_PLATFORM='offscreen'
.\.venv\Scripts\python.exe -m unittest -q test_ai_api_settings_ui test_memory_settings_ui test_direct_cut_startup
.\.venv\Scripts\python.exe -m unittest -q test_product_release
.\.venv\Scripts\python.exe -m unittest discover -q
node --check .\pr_bridge\js\main.js
```

- 改参数传递：查看 `test_cut_strength.py`、队列和启动相关测试，验证界面、持久化、任务快照与实际执行使用同一值。
- 改内容和边界：查看 `test_source_timeline.py`、`test_model_editor.py`、`test_boundary_refiner.py`、`test_rendered_output_qc.py` 等，覆盖长无对白、连续游戏音、句首和尾音。
- 改缓存：验证身份、音轨、长路径、并发取消和重复读取；不要只检查某次缓存命中。
- 改 API：查看 `test_llm_gateway.py` 及相关配置测试；模拟各协议、失败响应、敏感参数和无 Key 场景。
- 改 PR：查看 `test_pr_workflow.py`、`test_pr_project_export.py`、`test_pr_bridge_extract.py`、`test_pr_subtitles.py`，再在真实 Premiere 检查打开、试听、改变片段时长与另存。
- 改字幕：至少覆盖低置信词和漏识窗口的局部复听、复听失败回退、术语保真、语义边界、15 字上限、词级时间、简繁同时间轴，以及“字幕失败不阻断视频/PR 工程”。使用真实音频时记录素材时间范围和音轨，不把模型跑通等同于字幕正确。
- 改安装与发布：`test_product_release.py` 使用临时目录与模拟命令检查缺文件、无 Python 启动器、依赖更新、干净配置及文档链接，不安装软件、不下载模型。

完整测试可能依赖 FFmpeg、模型、真实素材或 Premiere。报告精确命令和结果，把模拟测试、真实素材测试、真实 Premiere 验证分别说明；不要把“编译通过”写成“剪辑效果已验证”。复现问题时记录版本、入口、模式、保留百分比、音轨、源素材时长、任务 ID、问题发生的源时间与输出时间；不要公开原片或密钥。

## 让 AI 协助二次开发

每次只交给 AI 一个可验证的目标，先要求它读取相关模块和测试，列出当前行为和冲突，再实施。提供失败日志、片段时间范围和期望行为，比“全套优化一下”更容易得到可靠结果。可以使用下面的任务模板：

```text
你正在修改 SmartCut 智能剪辑助手。先阅读 README.md、docs/开发与构建.md、
product_info.py 以及本次相关的源码和测试。

目标：描述一个具体问题与完成标准。
复现：入口、模式、保留百分比、音轨、素材/输出时间范围、已脱敏日志。
允许修改：明确列出模块或职责范围。
限制：保留原工程和私人配置；不改无关 API/字幕逻辑；不上传素材或 Key；
      不把源时间、PR 时间和成片时间混用；不删除回归测试来掩盖失败。
执行：先找到原因与参数链，再小步修改；为真实风险补测试，复用统一判据。
交付：列出改动文件、实际测试命令/结果、尚需人工验证的部分及回滚方式。
```

按问题选择最小修改面：按钮样式只改 UI；新模型协议改适配层；切点问题先审查证据与坐标；PR 时间轴问题先审查快照、映射和执行事务。不要让 AI 同时更换模型、改字幕算法并重写工程格式，这会难以定位回归。

若多个 AI 同时协作，给每个代理指定互不重叠的文件，并在共享文件落笔前重读；不要覆盖尚未提交的用户改动。每次生成代码后查看差异，运行相应测试，再用短素材验证。发布或迁移前使用 Git 提交或项目快照保留可恢复版本。

## 构建与干净发布

```powershell
.\.venv\Scripts\python.exe .\build_tools\build_app.py
.\.venv\Scripts\python.exe .\build_tools\generate_compliance.py
.\.venv\Scripts\python.exe .\make_release.py
```

构建器使用 PyInstaller 并运行 Qt 冒烟测试。为兼容既有启动路径，当前正式 EXE 仍为 `智能剪辑助手.exe`；窗口、文件属性和教程显示 SmartCut 智能剪辑助手。EXE 与 `_internal` 必须来自同一次构建，不能只覆盖 EXE。

构建后还可以通过 EXE 自身运行字幕交付模块冒烟检查，排除同目录源码掩盖漏打包模块的情况：

```powershell
& '.\发布版\智能剪辑助手\智能剪辑助手.exe' --run-script "$PWD\build_tools\packaged_subtitle_smoke.py" "$PWD\packaged-subtitle-smoke.json"
```

命令退出码应为 `0`，并生成 `packaged-subtitle-smoke.json`。检查其中 `max_chars` 不大于 `15`，`modules` 包含 `pr_subtitles`、`pr_workflow`、`subtitle_quality` 和 `subtitles`。该检查只在本地验证语义断句与关键字幕模块可导入，不调用网络接口，不操作 Premiere，也不修改用户配置。

`make_release.py` 默认发布 `dist/SmartCutAssistant` source-bootstrap 包，带上 MIT 源码、README、docs、NOTICE、依赖清单、Premiere 插件源码和自动安装脚本，不要求本机先存在 PyInstaller EXE，也不复制 `智能剪辑助手.exe`、`_internal`、`.venv`、`runtime`、`bin` 或 `models`。接收者首次双击安装器时从上游来源安装依赖。只有显式构建离线二进制模式时，才检查并成套复制 EXE 与 `_internal`。

公开发布采用失败关闭门禁。以下内容缺一项时脚本会退出，并把同版本旧目录、ZIP 和校验文件移动到 `dist/_blocked/`，防止旧包被误认成本次成功产物：

- 项目根目录 MIT `LICENSE`；
- `requirements.lock`、CycloneDX `SBOM.cdx.json` 和与发布范围一致的说明；
- 发布目录和 ZIP 的绝对路径、常见 API Key/私钥扫描通过。

默认 source-bootstrap 包不重新分发已安装的 Python/Qt/FFmpeg/CTranslate2 二进制，因此 `LICENSES/manifest.json` 中针对离线 native runtime 的未完成项不会阻止该模式。发布 EXE、`_internal`、`runtime`、`bin` 或模型时，清单必须对实际载荷达到 `complete=true`；`--with-bin` 还要求 `LICENSES/bin/MANIFEST.json`，`--with-models` 还要求 `LICENSES/models/MANIFEST.json`。不要为了通过门禁伪造清单；应记录每个实际二进制或模型的来源、版本、许可证和对应文件。

`build_tools/generate_compliance.py` 会从当前 Python 环境生成精确版本的 `requirements.lock`、CycloneDX SBOM，并把已安装 distribution 中真实存在的 LICENSE/COPYING/NOTICE/ThirdPartyNotices 复制到 `LICENSES/python/`。若 wheel 漏带许可证正文，只能在 `LICENSES/python_overrides.json` 中登记版本固定的官方源码包或官方标签、来源 SHA256、正文路径和正文 SHA256；生成器会逐项复验。它同时在 `LICENSES/manifest.json` 的 `missing` 中列出找不到许可证的包；有任何缺失时 `complete=false` 且返回非零退出码。Qt、FFmpeg、模型等非 Python 二进制需人工核对后写入 `LICENSES/manual_components.json` 并放入真实许可证文本；尚未确认的组件应保留 `complete=false` 和具体原因，生成器不会猜测授权。

公开包只包含 `kb/01_*.txt` 至 `kb/10_*.txt` 这十份项目手工基础词库。`mods_terms.json`、`mods_hint.txt`、`术语_全量.txt`、`术语_键值.json` 和 `术语_统计.txt` 是从本机第三方模组资源生成的私有派生数据，可能包含本机路径且没有逐模组再分发授权，不进入仓库或发行包。用户可从自己合法持有的 `mods` 目录在本机重新生成。

本机 `conf/settings.json`、`conf/llm.json`、`conf/editor_model.json`、日志、工作目录、素材、私有派生词库和备份都不应进入公开包。发行包写入空的默认 settings 配置，不沿用开发者的 API Key、输出路径或模型选择。`.gitignore` 不是密钥扫描器；提交前仍要检查暂存内容、仓库历史和大文件。

发布前同步 `product_info.py`、`build_tools/version_info.txt`、README 与 NOTICE 中的版本。按 [发布检查清单](../RELEASE_CHECKLIST.md) 在全新目录解压验证安装、重复运行、普通视频、字幕、多音轨和可编辑 PR 工程。记录已知限制和需要用户检查的降级结果。
